# Bounded semantic retrieval experiments, 2026-10-01

The selected experiment is an **optional Jev reranker over up to 48 native candidates**. It improves one development question and one newly frozen confirmation question at the 2,048-source-token cap, with no evidence-recall regression in any question or repository/budget group. It adds roughly 350 ms of observed network/model time and about 16,000 provider input tokens per question. It does not recover evidence absent from retrieval. The Rust default is unchanged.

`semantic_search.py` makes this policy usable as a separate CLI, with explicit remote-call opt-in, cached replay, and native fallback on API/cache/validation errors. These are small retrieval experiments, not evidence of general agent-task improvement or statistical superiority.

## Frozen design and evaluation

- Source: the existing immutable `optimization-focused-20260916/snapshots` trees for AgentX, Flexcontext, and WebKit Python tooling. This is not full WebKit.
- Binary: accepted pass2 SHA-256 `06566aee38f5df57ff5886b7243ec7771df19297a503197dacf446242a88a324`.
- Development: the existing 18 development questions, six per repository, from `optimization-cases.json`. The old held-out split was not used to select the semantic policy.
- Confirmation: nine questions / 27 evidence atoms from new module families, authored by a separate agent and frozen before candidate selection. They are assistant-authored and source-checked, not independently adjudicated by a human. `confirmation-cases.json` SHA-256: `a04e4ae6f7a96067c579d22384afb5be6742f877c4bb688c565fe346b5570a34`.
- Model: pinned `jev-1.13.0`. Four unchanged, descriptive relevance levels. One independent Score question per candidate in a shared request. Neither gold labels, evidence spans, answer notes, benchmark split, nor native relevance scores enter prompts.
- Retrieval: the existing query-term adapter, native baseline policy, compact output, 100-result cap. Semantic scoring uses the 4k native overfetch response (32,768-source-byte ceiling), takes its first 48 candidates, sorts by descending Score with stable original-order ties, and appends the untouched tail. The existing `cl100k_base` complete-line prefix cap and source alignment are unchanged.
- Control: original native output at each budget, plus the same 4k overfetch without semantic reordering, capped identically. The overfetch control has the same evidence recall as original in the selected development and confirmation evaluations; the reported gain is not from increasing the overfetch allowance alone.
- Selection gate: no evidence-recall loss in any repository/budget group. The selected variant also has no individual question/budget recall loss.
- Freeze before confirmation retrieval: `.benchmark-results/semantic-native48-confirmation-20261001-freeze.json`. Selected design hash `15e6e822087326d25d3265f61c7e50ef12f0c28d8e005f1903f2e756de72c39a`; scorer hash `e7a209730d437694ffd85bebc8e33143d6ca50b78bdc089322fecd50a3eed17f`; adapter hash `1b1466c60d8365977e640c271821bb46cd1f049db046139dde042a1a84b2ae43`.

The integration follows the live [TypeSafe HTTP API](https://docs.typesafe.ai/api), [reranking cookbook](https://docs.typesafe.ai/cookbooks/rerank_typesafe), and [Score primitive](https://docs.typesafe.ai/primitives/score). Arithmetic, candidate identity, budgets, and output selection remain deterministic code.

## Development results and rejected designs

Values are mean evidence-atom recall at 2k / 4k; every repository has six development questions.

| Experiment | AgentX | Flexcontext | WebKit Python | Decision |
|---|---:|---:|---:|---|
| Original baseline | 83.33% / 100% | 100% / 100% | 50% / 50% | Reference |
| Jev, original top24 | 83.33% / 100% | 100% / 100% | 50% / 50% | No recall gain; reject overhead |
| Qwen two-query expansion + stable RRF | 100% / 100% | 83.33% / 83.33% | 33.33% / 33.33% | Reject regressions |
| Jev on RRF top24 | 100% / 100% | 83.33% / 83.33% | 33.33% / 33.33% | Reject regressions |
| Jev48, original top24 preserved before expanded candidates | 100% / 100% | 100% / 100% | 50% / 50% | Pass, but more complex and expensive |
| **Jev, original top48** | **100% / 100%** | **100% / 100%** | **50% / 50%** | **Selected simpler ablation** |

The original top24 omits `v2-url-origin` evidence despite its presence in the full native response. Expanding the scored native shortlist to 48 supplies it and makes the 2k context complete. Three WebKit questions remain missing from even the full native response. Changing their ordering cannot fix those omissions.

The Qwen experiment sends only the natural-language question, requests two complementary two-to-six-word search strings, retains the original query, and combines the three native lists using stable reciprocal-rank fusion with fixed `k=60`. This improved the URL question but pushed `v2-index-fields` and `v2-memo-call` evidence below the top24 scored shortlist. Preserving original candidates repaired those regressions; the original-only 48-candidate ablation achieved the same recall without Qwen. No prompt or rubric was tuned to individual questions. All variants and failed gates remain recorded.

Qwen used `Qwen/Qwen3.6-35B-A3B-FP8`, temperature 0, max 256 output tokens, with thinking disabled. The endpoint and model catalog were verified against [official Hetzner documentation](https://docs.hetzner.com/general/company-and-policy/experiments/inference/) and an authenticated model-list request. The [Qwen model card](https://huggingface.co/Qwen/Qwen3.6-35B-A3B) documents the thinking switch. Requests were paced at least 6.2 seconds apart after completion and coordinated with the separate agent evaluation.

## Locked confirmation

The nine confirmation questions were used once after the design freeze. Each repository has three questions; values are evidence recall.

| Repository | Original 2k | Jev48 2k | Original 4k | Jev48 4k |
|---|---:|---:|---:|---:|
| AgentX | 44.44% | 44.44% | 44.44% | 44.44% |
| Flexcontext | 66.67% | **100%** | 100% | 100% |
| WebKit Python | 66.67% | 66.67% | 66.67% | 66.67% |
| **All nine questions** | **59.26%** | **70.37%** | **70.37%** | **70.37%** |

Across both budgets: **one win, 17 ties, zero losses**. Aggregate recall rises from 64.81% to 70.37%. Mean region-based precision changes from 9.51% to 10.78% at 2k and 5.53% to 5.51% at 4k. Semantic ranking is not a precision improvement everywhere.

Candidate coverage explains the remaining ceiling: `confirm-release-fallback` and `confirm-attribute-restore` have no evidence in the complete native candidate set; `confirm-environment-loading` and `confirm-unique-credentials` each have only two of three evidence atoms. Jev does not create missing source or broaden this candidate pool.

Fresh comparator scores were released only after the semantic design froze: Probe 48.15% / 48.15%; CodeGraph explore 66.67% / 66.67%; CodeGraph get-context 48.15% / 48.15%; native Flexcontext 59.26% / 70.37%, at 2k / 4k. Jev48 reaches 70.37% / 70.37%. The tiny corpus, different tool workflows, and additional inference cost limit any broader conclusion; see the separate comparator report for its interface and source-attribution limitations.

## Actual inference and source overhead

API times include network and provider processing. Each question has one observed live request per experiment; these are median and maximum observations, **not a repeated latency benchmark or production p95**. Cached replay is excluded from live timing. Costs use the documented Jev input rate of $0.042 / million tokens and free output from the [current model documentation](https://docs.typesafe.ai/models); they are estimates, not billing receipts.

| Experiment | Live requests | Input tokens | Output tokens | Median / max API ms | Estimated Jev input cost |
|---|---:|---:|---:|---:|---:|
| Original top24 development | 18 | 168,133 | 6,804 | 295.08 / 347.95 | $0.007062 |
| Qwen expansion development | 18 | 2,274 | 312 | 767.76 / 2,280.99 | Free experimental endpoint |
| RRF top24 + Jev development | 18 | 157,549 | 6,804 | 296.83 / 570.47 | $0.006617, plus expansion |
| Preserved union48 + Jev development | 18 | 326,968 | 13,716 | 370.20 / 492.44 | $0.013733, plus expansion |
| **Original top48 development** | **18** | **289,606** | **12,276** | **352.97 / 391.66** | **$0.012163** |
| **Original top48 confirmation** | **9** | **149,175** | **6,090** | **345.80 / 415.44** | **$0.006265** |

All four Jev development experiments plus confirmation used 1,091,431 input tokens and 45,690 output tokens, estimated $0.045840 total. One early Qwen request was interrupted before a response when coordinating shared rate limits; it is not included in measured usage because no usage was returned. It may still have consumed service capacity.

For selected native48 development, model-visible candidate source alone totals **518,580 characters / 117,100 cl100k tokens** across 18 queries; confirmation totals **277,230 characters / 63,060 cl100k tokens** across nine. Mean provider input is 16,089 development / 16,575 confirmation tokens per query, including questions and API formatting. Output source remains capped at 2,048 or 4,096 tokens. These costs must not be mistaken for only the final returned-context budget.

Qwen expansion triples retrieval calls. Development union retrieval inspected, on average per question, 10,245–11,800 source tokens at the 2k cap and 19,476–23,152 at the 4k cap, depending on repository. Those additional source tokens are tracked separately from the small Qwen rewrite prompt and the downstream Jev request.

The selected approach reduces the retained context needed for two observed questions, but adds substantial total model input. It is useful only where answer-context scarcity matters enough to justify remote source handling, roughly 0.35 seconds added model latency, and inference tokens. It is not an unqualified token-efficiency improvement.

## Reproduce and use

Dependencies use the existing `.benchmark-venv`; no new package is required. Caches under ignored `.benchmark-results/semantic-jev-cache` and `semantic-qwen-cache` retain exact request bodies, raw responses, provider usage, and measured timings. They contain source excerpts, **never credentials**. Secrets are read only from environment variables. Cache keys hash canonical requests. Both native budget artifacts are hashed in run contracts.

```sh
# Reproduce selected development quality without another API call.
.benchmark-venv/bin/python benchmarks/comparison/semantic_native48.py \
  --artifacts .benchmark-results/iteration-20261001-pass2-accepted/artifacts \
  --snapshot-root .benchmark-results/optimization-focused-20260916/snapshots \
  --output .benchmark-results/semantic-native48-replay \
  --cache .benchmark-results/semantic-jev-cache

# Reproduce locked confirmation quality without another API call.
.benchmark-venv/bin/python benchmarks/comparison/semantic_native48.py \
  --artifacts .benchmark-results/semantic-native48-confirmation-source-20261001/artifacts \
  --snapshot-root .benchmark-results/optimization-focused-20260916/snapshots \
  --cases benchmarks/comparison/confirmation-cases.json --split heldout \
  --output .benchmark-results/semantic-confirmation-replay \
  --cache .benchmark-results/semantic-jev-cache

# Optional local CLI. Add --live to permit sending source to TypeSafe;
# set JEV_API_KEY in the process environment. No key is needed for replay.
.benchmark-venv/bin/python benchmarks/comparison/semantic_search.py \
  /path/to/repository 'How does this code handle the requested behavior?' \
  --binary target/release/flexcontext --budget 2048 \
  --cache .benchmark-results/semantic-user-cache

.benchmark-venv/bin/python -m unittest discover \
  -s benchmarks/comparison -p test_semantic_rerank.py
```

The standalone CLI returns budgeted source records with original paths/line numbers and explicit semantic metadata. It uses a three-second network socket timeout and no retries by default. Missing credentials, cache misses without `--live`, malformed responses, and network errors fall back to the original native response at the requested budget. Stable, nonsecret reason codes distinguish `cache_miss`, `missing_api_key`, `invalid_cache`, `api_timeout`, HTTP authorization/rate-limit failures, malformed responses, and transport failures. Native RPC/tool errors and missing source produce structured error codes and exit nonzero. The socket timeout is not a strict overall process deadline: native startup/retrieval and DNS/system behavior are separate. This prototype starts a new native server process per invocation; its total CLI latency is not the resident retrieval latency in earlier reports.

Twelve targeted tests pass, covering prompt field exclusion, stable ties/tail retention, rejection of missing/nonfinite/boolean scores, RRF candidate handling, rewrite validation, exact baseline fallback on timeout/malformed cache/truncated HTTP responses, sanitized reason codes, native-error/nonzero-exit behavior, and source-line preservation when files are deleted during remote work. Source records are aligned and frozen before inference, but capture is not atomic with native retrieval: earlier edits can leave unresolved line numbers, explicitly indicated by `source_alignment_complete: false`. Unavailable source yields an explicit error and nonzero exit. Full confirmation replay returns exactly identical quality rows. Live-wrapper cache replay and cache-miss fallback both reproduce their respective saved confirmation source records exactly. Qwen cached replay reproduces its selected source and quality, with freshly measured retrieval times kept separate.
