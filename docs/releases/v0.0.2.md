Resident MCP searches now automatically check index freshness after file edits,
additions, renames, and deletions. Coding agents can search again after editing
without calling `refresh_index`. Unchanged source reuses the in-memory index;
explicit refresh remains available. Includes the October 29 implementation
merged in [#4](https://github.com/thamok/Flexcontext/pull/4).

Freshness detection is metadata-based (size/mtime and Unix device/inode/ctime),
not a content hash. A same-size in-place overwrite that preserves all these
values can remain stale, including very rapid writes within one filesystem
timestamp tick. Concurrent edits during a scan are also not transactional.
For this edge case, an atomic file replacement changes the inode; alternatively,
remove `.flexcontext/index.json` before calling `refresh_index` to force a reparse.
This release preserves the existing metadata-based design and scan costs.

### Verified binaries

- `aarch64-apple-darwin`: native Apple Silicon, built and executed on macOS 14.
- `x86_64-unknown-linux-gnu`: native Linux x86-64, built and executed on Ubuntu 22.04 (glibc 2.35).

Both targets pass formatting, Clippy with warnings denied, the Rust tests, release
builds, and benchmark smoke checks. Separately, the executable extracted from each
archive passes CLI version/help/search checks and resident MCP execution tests
for both supported protocols: edit, unchanged-index reuse, add, rename, and delete.
These execution tests use one server process per protocol and never call `refresh_index`.
The same-length edit explicitly advances mtime to avoid filesystem tick races.
The cancellation recovery unit test also uses a deterministic metadata change
and runs 50 additional times per native release target.
Intel macOS, Linux ARM, and Windows binaries are not published or verified.
macOS binaries are not Developer ID signed or notarized.

### Install or upgrade

Download the archive for your platform and `SHA256SUMS` from this release.
For Apple Silicon:

```sh
shasum -a 256 -c SHA256SUMS --ignore-missing
```

```sh
tar -xzf flexcontext-v0.0.2-aarch64-apple-darwin.tar.gz
```

Install to a directory on your PATH (use the existing executable's path when upgrading):

```sh
mkdir -p "$HOME/.local/bin"
```

```sh
install -m 755 flexcontext "$HOME/.local/bin/flexcontext"
```

```sh
flexcontext --version
```

Expect `flexcontext 0.0.2`. Ensure `$HOME/.local/bin` is on PATH and check
`command -v flexcontext` for another installation taking precedence. Restart
Codex or your MCP client to replace any resident 0.0.1 process. On Linux, use
the `x86_64-unknown-linux-gnu` archive and `sha256sum --check --ignore-missing SHA256SUMS`.

Alternatively, build this exact release from source:

```sh
cargo install --git https://github.com/thamok/Flexcontext.git --tag v0.0.2 --locked --bin flexcontext --force
```

Each archive contains the executable, MIT license, and `BUILD_INFO.json` recording
the exact source commit, target, Rust toolchain, lockfile hash, binary SHA-256,
and workflow URL. `SHA256SUMS` covers the downloadable archives. The publication
job verifies source identity and hashes, then downloads and checks the uploaded
assets before making the draft release public. Builds pin Rust 1.99.1 and use
the committed lockfile; byte-for-byte reproducibility across runner image updates
is not claimed.
